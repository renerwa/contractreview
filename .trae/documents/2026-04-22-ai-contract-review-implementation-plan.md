# AI 合同审核项目实施计划

## 1. 目标

将当前通用 AI SaaS 模板项目改造成一个面向欧美用户的 AI 合同审核产品，形成完整的三段式用户链路：

1. `Landing Page`
2. `合同详情页`
3. `正式审核结果页`

在保留现有主题动态页机制与合同解析/预分析/审核后端骨架的前提下，重组前端交互、匿名会话、登录转化与审核结果交付方式。

## 2. 已确认的产品约束

- 目标用户优先为企业法务，兼顾创始人、采购、销售和商务团队。
- 产品主要面向欧美用户，首页风格以专业法律工具为主，带适度 AI 科技感。
- 站点默认语言为英文；如果浏览器语言或地区命中支持语言（当前为英文、中文），且与当前站点语言不同，则提示用户手动切换。
- 用户选择的站点语言作为全局语言偏好，预分析后的表单语言及其他页面语言默认沿用，除非用户主动切换。
- 游客能力只开放到预分析和审核设置填写，正式审核前要求登录。
- 首页默认主推 `上传文件`，`粘贴内容` 为次选入口。
- 首页不提前强调登录门槛，采用渐进式转化：用户先完成预分析后的信息补充，再在正式审核前要求登录。
- 首页提交后最多停留 10 秒，每 2 秒轮询一次预分析结果，共 5 次。
- 若 10 秒内结果就绪，则立即跳到单份合同详情页并提示成功。
- 若 10 秒仍未完成，则 10 秒后跳到单份合同详情页继续等待。
- 合同详情页采用“顶部状态区 + 下方内容区”结构。
- 详情页顶部使用直白 4 步流程：`Upload / Extract / Pre-analysis / Review setup`。
- 详情页等待阶段需在专业基础上加入 AI 正在理解合同的动态感与科技元素。
- 预分析必须先判断“这是不是合同”；非合同则终止后续流程，并提供重新上传或改为粘贴文本的主操作。
- 预分析完成后，摘要和补充表单同时出现；桌面端可左右并列，移动端上下堆叠。
- 审核立场默认中立。
- 若系统识别到签约国家，则在审核设置表单中默认填好，但允许用户手动修改。
- 输出语言默认沿用用户选择的站点语言，而不是合同语言。
- “重点关注事项”先由用户自由输入，再由 AI 整理为结构化要点供后续审核使用。
- 用户填写完审核设置后，先展示短暂 preparing 动画，再弹出登录框。
- 登录弹窗的主理由是“开始完整审核”。
- 登录弹窗可关闭，但页面需保留明显的“开始完整审核”入口。
- 第一期开启 `Google + 邮箱登录`，其中 Google 为主推入口。
- 数据库中的重点审查点不按国家存储，只作为基础框架。
- 正式审核时，模型需结合合同内容与签约国家动态补充或调整审查点。
- 未知合同类型需在本次流程中即时入库，并由多模型生成初始审核点，参与本次正式审核。
- 正式审核结果页第一屏突出总体风险等级，并展示高/中/低风险数量与关键结论摘要。
- 风险明细按风险等级降序展示。
- 单条风险卡片默认展示：标题、等级、简短结论；展开后按“原文 -> 风险说明 -> 修改建议”呈现。
- 结果页主动作是导出 PDF 审核报告。
- PDF 报告包含：风险总览、风险明细、合同摘要、完整审核设置信息。
- 第一期不支持重新审核。

## 3. 当前代码基线

### 3.1 首页与动态页面

- 首页入口：`src/app/[locale]/(landing)/page.tsx`
- 动态页面渲染：`src/themes/default/pages/dynamic-page.tsx`
- 当前首页主业务块：`src/themes/default/blocks/hero.tsx`
- 首页中文配置：`src/config/locale/messages/zh/pages/index.json`
- 首页英文配置：`src/config/locale/messages/en/pages/index.json`

### 3.2 合同相关后端接口

- 上传：`src/app/api/contracts/upload/route.ts`
- 启动解析：`src/app/api/contracts/parse/start/route.ts`
- 查询解析：`src/app/api/contracts/parse/query/route.ts`
- 预分析：`src/app/api/contracts/pre-analysis/route.ts`
- 启动审核：`src/app/api/contracts/review/start/route.ts`
- 查询审核：`src/app/api/contracts/review/query/route.ts`

### 3.3 合同核心服务与模型

- 预分析服务：`src/shared/services/contract_pre_analysis.ts`
- 合同识别/总结服务：`src/shared/services/contract.ts`
- 审核服务：`src/shared/services/contract_review.ts`
- 文档解析服务：`src/shared/services/document_parsing.ts`
- 文档模型：`src/shared/models/document.ts`
- 分析结果模型：`src/shared/models/analysis_result.ts`
- 合同类型模型：`src/shared/models/contract_type.ts`
- 审核点模型：`src/shared/models/contract_review_checklist.ts`
- 数据库结构：`src/config/db/schema.sqlite.ts`

## 4. 核心差距

### 4.1 产品流程与前端职责不匹配

- 当前 `hero.tsx` 同时承担首页展示、上传、解析轮询、预分析展示等职责，过于臃肿。
- 当前首页主链路只跑到“上传/解析/预分析”，没有完整的详情页承接、登录拦截与结果页交付。

### 4.2 匿名会话能力缺失

- 当前上传接口更偏登录用户流程，而目标产品要求游客可先上传、预分析、填写审核设置，再在正式审核前登录。
- 需要补“当前浏览器有效”的匿名会话绑定与登录后的任务归属迁移。

### 4.3 审核链路需要产品化包装

- 审核 API 与审核服务已有骨架，但缺少：
  - 登录拦截后的自动衔接
  - 正式结果页
  - PDF 导出
  - 未知类型即时建档与多模型审核点生成的产品级编排

## 5. 实施阶段

### Phase 1：梳理匿名会话、鉴权边界与状态机

目标：先打通游客可完成上传、解析、预分析、审核设置填写，但正式审核前必须登录的最小权限边界。

主要工作：

1. 梳理现有上传接口、预分析接口、审核接口的鉴权要求。
2. 设计并落地“当前浏览器有效”的匿名合同会话。
3. 明确匿名任务在登录成功后的归属迁移方式。
4. 统一前后端状态机，至少覆盖：
   - `uploaded`
   - `extracting`
   - `pre_analyzing`
   - `non_contract`
   - `review_setup_ready`
   - `awaiting_login`
   - `reviewing`
   - `review_done`
   - `review_failed`

重点文件：

- `src/app/api/contracts/upload/route.ts`
- `src/app/api/contracts/pre-analysis/route.ts`
- `src/shared/models/document.ts`
- `src/config/db/schema.sqlite.ts`

### Phase 2：首页改造为“获客 + 发起任务”

目标：保留动态首页机制，把首页变成专业获客页和任务发起页，不再承载复杂的后续状态。

主要工作：

1. 保留 `src/app/[locale]/(landing)/page.tsx` 入口和 `dynamic-page.tsx` 机制。
2. 拆分 `hero.tsx` 的职责，只保留：
   - 首屏视觉与价值主张
   - 上传文件 / 粘贴文本入口
   - 提交动作
   - 首页 10 秒缓冲轮询
3. 通过多语言配置和新增 block 重构首页区块：
   - Hero
   - Supported Contract Types
   - Why This Review Is Trustworthy
   - Sample Review Output
   - How It Works
   - Security & Privacy
   - FAQ
   - Final CTA
4. 改写首页文案与 SEO 内容，围绕企业法务用户和合同风险审查场景。

重点文件：

- `src/themes/default/blocks/hero.tsx`
- `src/config/locale/messages/zh/pages/index.json`
- `src/config/locale/messages/en/pages/index.json`
- 新增的 landing blocks

### Phase 3：新增单份合同详情页

目标：把长耗时等待、非合同拦截、预分析摘要、审核设置和登录前转化迁移到单份合同详情页。

主要工作：

1. 新增单份合同详情页路由。
2. 落地“顶部状态区 + 下方内容区”的主结构。
3. 实现状态切换：
   - Extract 等待态
   - 非合同拦截态
   - 预分析完成态
4. 在预分析完成态实现：
   - 左侧摘要
   - 右侧审核设置表单
5. 落地审核设置默认值规则：
   - 立场默认中立
   - 国家预填可改
   - 输出语言跟随站点语言
   - 重点关注事项自由输入
6. 新增“保存审核设置”能力，使匿名状态下也可提交这些信息。

重点文件：

- 新增详情页路由文件
- `src/shared/services/contract_pre_analysis.ts`
- `src/shared/models/document.ts`
- `src/shared/models/analysis_result.ts`

### Phase 4：登录拦截与匿名任务绑定

目标：在用户完成预分析和审核设置填写后，用低打断的方式完成登录转化。

主要工作：

1. 在详情页“保存并继续”后展示短暂 preparing 动画。
2. 复用现有登录弹窗组件，改写为“开始完整审核”的文案语境。
3. 设置登录方式优先级：
   - Google 为主按钮
   - 邮箱登录为次入口
4. 保证登录弹窗可关闭，但详情页保留明显 CTA。
5. 登录成功后：
   - 绑定匿名合同到用户账号
   - 保留匿名阶段已完成的预分析与审核设置
   - 自动进入正式审核

重点文件：

- 现有登录弹窗组件与登录相关页面
- 详情页主组件
- 合同与用户绑定相关模型/服务

### Phase 5：正式审核链路改造

目标：在现有审核骨架上，按确认过的产品规则补齐正式审核的输入、未知类型处理和执行衔接。

主要工作：

1. 保留现有审核后端骨架：
   - `src/app/api/contracts/review/start/route.ts`
   - `src/app/api/contracts/review/query/route.ts`
   - `src/shared/services/contract_review.ts`
2. 扩展审核输入，确保传入：
   - 合同正文
   - 审核立场
   - 签约国家
   - 输出语言
   - 用户重点关注事项（经 AI 整理后）
3. 明确审核原则：
   - 数据库审核点只作为基础框架
   - 模型必须结合签约国家与正文动态补充或调整审查点
4. 为未知合同类型补完整即时处理链路：
   - 即时建档
   - 使用 3 个模型生成初始审核点
   - 聚合结果
   - 在本次正式审核中生效
5. 非合同文档禁止进入正式审核。

### Phase 6：结果页与 PDF 导出

目标：把正式审核结果组织成可阅读、可导出、可流转的专业交付页。

主要工作：

1. 新增结果页或在详情页中切换到独立结果视图。
2. 结果页第一屏固定为：
   - 总体风险等级
   - 高/中/低风险数量
   - 关键结论摘要
   - 导出 PDF 按钮
3. 风险明细区按风险等级降序展示。
4. 单条风险卡片结构为：
   - 默认：标题、等级、简短结论
   - 展开：原文 -> 风险说明 -> 修改建议
5. 第一版不支持重新审核。
6. 新增 PDF 导出链路，输出：
   - 风险总览
   - 风险明细
   - 合同摘要
   - 审核设置信息

### Phase 7：SEO、多语言与内容收尾

目标：让首页内容真正服务于 Google/Bing 获取用户，同时与产品定位保持一致。

主要工作：

1. 英文优先重写首页文案，中文同步维护。
2. FAQ 采用真实搜索问题表达方式。
3. 合同类型区块按分组 + 说明文字组织。
4. 落地语言提示策略与语言持久化体验。

## 6. 推荐开发顺序

1. 匿名会话与权限边界
2. 首页 Hero 与 10 秒缓冲跳转
3. 单份合同详情页
4. 登录拦截与匿名任务绑定
5. 正式审核链路与未知类型即时处理
6. 审核结果页
7. PDF 导出
8. SEO 与多语言文案收尾

## 7. 风险与难点

- 最大难点不是 UI，而是匿名预分析、登录后绑定和状态机设计。
- MinerU 解析慢，要求详情页轮询与状态承接足够稳。
- 当前审核查询接口兼具执行职责，如审核时长较长，结果页等待态设计要谨慎。
- 未知类型即时生成审核点会拉长正式审核启动时间，需要清晰的 loading 反馈。

## 8. 验收标准

- 游客在不登录的情况下，可完成：
  - 上传或粘贴合同
  - 预分析
  - 审核设置填写
- 首页提交后最多 10 秒缓冲，再稳定跳转详情页。
- 非合同文档会被明确拦截，并提供恢复操作。
- 登录后不丢失匿名阶段已完成的数据。
- 正式审核结果页符合既定结构，且无“重新审核”入口。
- PDF 导出成功，且包含总览、明细、摘要、审核设置信息。
- 中英文首页内容、语言跟随逻辑和 SEO 区块均按方案工作。

## 9. 立即执行的第一步

先从“匿名会话、上传接口与状态机边界”开始实现，再进入首页 `hero` 职责拆分和详情页承接。
